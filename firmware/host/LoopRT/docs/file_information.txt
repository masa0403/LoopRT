# Design Decision Record

## Decision: Delay Dispatcher Implementation

Date:
2026-07-31

Context:
LoopRT architecture discussion identified that Command Dispatcher separation
provides better long-term scalability.

However, current development priority is achieving the first complete execution
loop as soon as possible.

Decision:
Dispatcher implementation is intentionally postponed.

Until First Loop completion:
- Executor directly interprets CommandType.
- Command execution logic remains inside Executor.
- No Handler abstraction is introduced.

After First Loop completion:
Revisit this design point and implement:

Command
  |
Dispatcher
  |
Handler
  |
Hardware Driver

Reason:
Prioritize functional validation and developer momentum over premature abstraction.

========================================
Command.h / Command.cpp
========================================

役割
- Command種類を保持
- execute()で種類に応じた処理を実行

現在はCommand自身が命令データと実行処理を保持している。

定義

- CommandType
  - PinHigh
  - PinLow
  - Delay
  - End

クラス
Command

保持:
- CommandType type

初期状態:
CommandType::None

公開関数:
- Command()
- Command(CommandType type)
- execute()
- isEnd()

処理:
Command::execute()でCommandTypeに応じた処理を実行する。
Command(CommandType type) コンストラクタを追加

現在の動作:

PinHigh:
- D13をHIGHに設定

PinLow:
- D13をLOWに設定

Delay:
- 1000ms待機

End:
- 終了命令として扱う

現在:
Commandが実際のArduino GPIOを操作可能。

========================================
CommandReader.h / CommandReader.cpp
========================================

役割
命令(Command)を取得するためのインターフェース。

現在、固定Programを返す。

クラス
int index
CommandReader

変更

read():
- Serial入力を待機
- 受信文字をCommandへ変換
- CR/LFは無視

Command mapping:
- H → PinHigh
- D → Delay
- L → PinLow
- E → End

現在:
Python / Serial MonitorからCommandを受信可能。


未実装:
- Flash読み込み
- Program保存領域
- バイナリCommand読込

将来的にはProgramがCommandを取得する入口になる。
